## 0. デザイン原則

1. **デザインの正は `design-system/`（rev.3「海図と水面の光」）。** 全画面を `design-system/styles.css` のトークン（`--color-*`/`--font-*`/`--radius-*`/`--shadow-*`）とコンポーネントクラス（`.ds-*`）で組む。旧v1のClaude-paperトークン（terra/sage/dijon・globals.css）は**使わない**（v2画面ごと削除予定・PRD §5のオーナー裁定 2026-07-25）。**リプレイ画面の海面は常時ダーク**: 反省会＝暗い部屋のプロジェクタ投影が本番のため、Canvasとその直近コントロール一式は `.ds-chart-surface`（海図面）＋`--gradient-water-deep` に固定し、サイトのライト/ダーク設定に連動させない（rev.3で「海はUIのテーマ設定に関係なく常に深い」として`:root`固定トークン化済み。ADR-001のSPIKE screenshotが実測済みの基準）。
2. **デバッガ比喩は操作の設計指針であって、画面の語彙ではない。** 部員は非エンジニア。UI上の文言は日常語に翻訳する。

   | デバッガの概念 | UI操作 | 画面上の呼び方 |
   |---|---|---|
   | ステップ実行・speed | 再生/一時停止・1x/4x/8x | 「再生」「速さ」 |
   | ブレークポイント | レグ頭出し | 「レグ」チップ（スタート/上マーク/下マーク/フィニッシュ） |
   | ウォッチ式（変数比較） | 2艇ハイライト | 「比較する2艇」チェック |
   | コメント/issue | タイムライン注釈 | 「メモを残す」「反省メモ」 |
   | PRレビューへのリンク | 注釈込みURL共有 | 「この場面のURLをコピー」 |

3. **遠目・高コントラスト。** プロジェクタ投影を基準に、再生画面の主要数値（時刻・速度・艇ラベル）は最低16px相当・太字・高コントラストで組む。マウスホバー前提の微小UI（8px未満のハンドル等）を主要操作に置かない。
4. **スマホは事後の見返し（縦画面）が主用途。** 反省会中の操作はPC/プロジェクタ想定だが、着艇後や移動中にスマホで同じURLを開いても迷わないよう、再生画面は縦画面で「Canvas→コントロール→タイムライン→注釈」の1カラム積み上げに畳む。
5. **PRDにないものは描かない。** 自動解析数値（VMG・タック損失等）・ランキング・動画埋め込み・ライブ距離表示は本書のどの画面にも存在しない。2艇ハイライトは視覚的な強調のみで、派生指標は出さない。

## 1. ログイン画面（v1流用）

v1の認証画面をそのまま使う。新規デザイン投資はしない（本タスクのスコープ外）。

- **レイアウト**: `.form-page`（v1既存クラス）を継続使用。中央カード・タイトル・email/passwordフォーム・送信ボタン・register導線。
- **状態**: 空（初期表示）/ 送信中（ボタンdisabled+ラベル変化）/ エラー（エラー帯でメッセージ表示）。
- **インタラクション**: **送信成功で `/sessions`（セッション一覧）へ遷移**（現行実装は旧ホームへ遷移しており要修正。v2画面削除=T-26と同時に直す）。
- v2画面削除（T-26）後もログイン/登録画面は存続。その時点でスタイルだけ`.ds-field`系へ寄せる（レイアウト変更はしない）。
- **モックアップは作らない**（既存v1画面を流用のため差分なし）。

### 状態
- **空**: rev.3の空状態パターン（モックアップ`sessions-list.html`の状態デモ準拠）。「まだセッションがありません」＋「最初のセッションをアップロード」CTA。
- **ロード中**: カード3枚分のスケルトン（`--color-fill`のシマー、角丸のみ・文字なし）。
- **エラー**: 一覧取得403/500時はページ上部にエラー帯（`--color-danger-tint`背景）＋再試行ボタン。帯には`role="status"`を付ける（§7 #6）。
- **権限なし**（他Teamのセッション詳細への直接URLアクセス）: 一覧自体はTeamスコープでしか取得しないため一覧に出現しない。詳細への直リンクは`/sessions/[id]`側の403画面（3章参照）で扱う。

### インタラクション
- フィルタチップ（`.ds-chip`）でpractice/raceを絞り込み。
- カードクリックでリプレイへ。アップロード直後はアップロード画面からの遷移でこのリストを経由しない（FLOWS.md: 保存後は直接リプレイへ）。

### スマホ変形
- ナビはモバイルで下部タブバー（`.ds-tabbar`）へ切替（モックアップ実装済みパターン）。フィルタバーは横スクロール可能な1行チップ列のまま。
- カードは1カラム、風況メモは2行までのクランプ表示。

### レイアウト（デスクトップ）

```
┌─────────────────────────────────────────────────────────┐
│ ページヘッダ:「セッションを登録」                            │
├─────────────────────────────────────────────────────────┤
│ Step 1: 基本情報                                          │
│   [タイトル___________]  種別:(◉練習 ○レース)  日時:[____]  │
│   会場:[____________]  メモ:[__________________]         │
├─────────────────────────────────────────────────────────┤
│ Step 2: GPXファイル（複数選択可・艇ごとにラベル付け）          │
│  ┌───────────────────────────────────────────────┐     │
│  │  ここにGPXをドラッグ&ドロップ / [ファイルを選択]        │     │
│  └───────────────────────────────────────────────┘     │
│  取り込み済み:                                             │
│   ● 4423_track.gpx  → 艇名[4423 田中/佐藤_____] ✓ 解析OK  │
│   ● manebtt.gpx     → 艇名[マネ艇_____________] ✓ 解析OK  │
│   ✕ corrupt.gpx     → 解析エラー: GPX形式が不正です [削除]  │
├─────────────────────────────────────────────────────────┤
│ プレビュー: 全艇の航跡を薄いラインで重ね描き（Canvas・時刻同期確認用）│
├─────────────────────────────────────────────────────────┤
│                              [一覧に戻る]  [保存してリプレイを開く]│
└─────────────────────────────────────────────────────────┘
```

- Step1は`.ds-field`＋`.ds-label`＋`.ds-input`で組み、**各`<label>`は`for`属性で入力に関連付ける**（§7 #5）。Step2のドロップゾーンは破線ボーダー意匠で、**`<button>`＋実`<input type="file">`（`.ds-visually-hidden`で視覚非表示・フォーカス可能）として実装**し、クリック可能divにしない（§7 #4）。
- 各行のファイル名はサーバ検証前でも即座に一覧化し、解析（DOMParser・フロント側／ARCH ADR-006）結果を行内バッジで即時反映する。

### 状態
- **空**（ファイル未選択）: ドロップゾーンのみ表示、保存ボタンはdisabled。
- **ロード中**（アップロード送信中）: 保存ボタンがスピナー付きdisabled、Step2はロック。
- **エラー**: 個別ファイルの解析エラーは行内（`.ds-field-hint--error`）に表示し全体送信をブロックしない（不正な1艇を除外して他艇は保存できる）。サーバ再検証（400/413）はページ上部のエラー帯に表示。**alert()は使わない**（§7 #6）。
- **権限なし**: 非TeamMemberはこのページ自体へのナビリンクが出ない（一覧・navbarから遷移しない）ため、直URLアクセス時のみ403画面（3画面共通の403）。

### インタラクション
- 艇名ラベルは自由入力（Track.boatLabelは自由記入・User非紐付け）。
- 「保存してリプレイを開く」がFLOWS.mdの主動線。「一覧に戻る」は複数セッションをまとめて登録する運用のための保持。

### スマホ変形
- Step1/Step2/プレビューを縦積み。ドラッグ&ドロップは非表示にし「ファイルを選択」ボタンのみ（タッチ環境でのDnD非対応を前提）。

## 4. リプレイ画面（`/sessions/[id]`）— 最重要画面

### 4.1 デザイン意図

反省会のプロジェクタ投影が主使用シーン。海面は常時ダークの海図面（`.ds-chart-surface`＋`--gradient-water-deep`＋緯度経度グリッド`--color-chart-grid-on-water`。rev.3の柱1・柱2）。オーナーの「デバッガのように」を、非エンジニア語彙のまま次の4操作に翻訳する: **再生/速さ**・**レグ**・**比較する2艇**・**メモ**。

### 4.2 レイアウト（デスクトップ・プロジェクタ想定＝横長）

```
┌───────────────────────────────────────────────────────────────────┐
│ ← 一覧へ   江の島 定期練習 2026-07-20            [URLをコピー 🔗]   │
├───────────────────────────────────────┬─────────────────────────┤
│                                         │ 比較する2艇（最大2）        │
│                                         │ ☑ ● 4423 田中/佐藤        │
│                                         │ ☐ ● マネ艇                │
│         Canvas（航跡・テール・現在位置）    │ ☑ ● 1102 鈴木/高橋        │
│         ダーク海面・スケールバー付き        │ ☐ ● 0091 山本/井上        │
│                                         │ ☐ ● 2200 中村/木村        │
│                                         │ ☐ ● 3311 小林/加藤        │
│                                         ├─────────────────────────┤
│                                         │ 反省メモ（このセッション）    │
│                                         │ 00:14:02 なんでここでタック?│
│                                         │  — 主将                  │
│                                         │ 00:22:40 良い加速         │
│                                         │  — 田中                  │
│                                         │ [＋ 今の場面にメモを残す]   │
├───────────────────────────────────────┴─────────────────────────┤
│ [▶ 再生]  速さ [1x][4x][8x]        00:14:02 / 02:03:11            │
│ ─●━━━━━━━━━━━━◆━━━━━━━━━━━━◆━━━━━━━━━━━●─  （タイムライン+注釈ピン）│
│ [スタート] [上マーク L1] [下マーク L2] [フィニッシュ]  （レグチップ）    │
└───────────────────────────────────────────────────────────────────┘
```

- **左（可変幅・主役）**: Canvas。ダーク海図面＋航跡ライン＋各艇の現在位置ドット＋航跡テール（チェックで表示/非表示）＋スケールバー（例: 500m）。
- **6艇の識別ルール（2026-07-25確定。本文6色案とモックアップ4色再利用の矛盾を解消）**: 色トークンは `--color-boat-1..4` の**4色のまま増やさない**（rev.3 DSに5色目以降は存在しない）。艇index 0〜3=実線×boat-1..4、**艇index 4〜5=boat-1/boat-2の再利用＋破線（dash）で線種を変える**。さらに**全艇の現在位置ドット脇に艇ラベル（セール番号等の短縮名）を常時描画**し、色だけに識別を依存させない（色覚多様性・プロジェクタの色再現差への耐性。§7 #8）。サイドバーのチェックリストの色スウォッチも同じ「色＋線種」見本で描く。
- **右サイドバー（固定320px）**: 「比較する2艇」チェックリスト＋「反省メモ」パネル。ARCH ADR-001の通り艇の色はfront側でindex固定割当（DB非永続化）なので、チェックボックスの色スウォッチは一覧表示順そのまま。
- **下部フルワイド帯**: 再生コントロール（大きい・遠目対応）＋タイムラインスクラブバー（注釈はピン◆で可視化、クリックでその時刻へジャンプ）＋レグチップ行（クリックでそのレグ開始時刻へジャンプ＝ブレークポイントの比喩）。

### 4.3 主要コンポーネント

| コンポーネント | 役割 | 備考 |
|---|---|---|
| Canvasビューポート | 航跡・テール・現在位置描画 | ARCH: rAF+ref駆動、Reactステートの外。UIへの同期は≦10Hz |
| 艇リスト（比較チェック） | 2艇ハイライト選択 | チェック2件超は先勝ちで古い方を自動解除（UIポップオーバー等は出さない・シンプルに） |
| 反省メモパネル | 注釈の閲覧・追加 | 追加時は現在の再生時刻(tSec)を自動キャプチャ。艇/レグの紐付けは任意（プルダウン省略可） |
| 再生コントロール | 再生/一時停止・速度切替 | 1x/4x/8xの3段階のみ（ARCH範囲外の速度は作らない） |
| タイムラインスクラブバー | シーク・注釈ピン表示 | ドラッグ中はプレビューのみ、確定（pointerup）時に`history.replaceState`（ARCH: シーク確定時のみURL書き込み） |
| レグチップ | レグ頭出し | `Session.legs`から生成。手動補正はMVPのUI外（PATCH APIはあるが編集UIは別タスク） |
| URLコピー | 現在の再生状態を共有 | `?t=&boats=&leg=`。コピー後トースト表示 |

### 4.4 状態

- **ロード中**: Canvas領域はダーク背景のまま中央にスピナー＋「航跡を読み込み中…」。コントロール類はdisabled。
- **空**（Track 0件のセッション ＝ 通常発生しないが不整合データ時）: Canvas中央に「このセッションには航跡データがありません」＋一覧へ戻る導線。
- **エラー**（取得失敗）: Canvas領域に警告表示＋再読み込みボタン。反省メモパネルは非表示。
- **権限なし**（非TeamMember）: リプレイ画面全体をダーク基調のまま「このセッションを見る権限がありません」403表示に置換（ライトテーマの汎用エラーページに落とさず、共有URLを踏んだ非部員にも同じダーク画面で一貫させる）。
- **注釈0件**: メモパネルは「まだメモがありません。反省会での気づきを残しましょう」の空状態文言＋追加ボタンのみ。

### 4.5 インタラクション詳細

- 再生中はタイムラインの再生ヘッドが自動で進み、Canvas上の艇も同期して移動（テール表示ON時は直近区間の軌跡を残す）。
- レグチップをクリック → 一時停止した上でそのレグ開始時刻にジャンプ（反省会で「じゃあ上マークから見せて」に対応）。
- 注釈ピン（◆）をクリック → その時刻にシークし、右パネルの該当メモをハイライト・スクロール。
- 「今の場面にメモを残す」→ 入力欄がインライン展開（モーダルを開かない・議論のテンポを止めない）。
- 「URLをコピー」→ 現在のtSec・チェック中の艇ID・直近通過レグをクエリに埋め込みコピー、トースト「URLをコピーしました」。

### 4.6 スマホ変形（縦画面）

```
┌───────────────────────┐
│ ← 一覧へ      🔗 共有   │
│ 江の島 定期練習          │
├───────────────────────┤
│                       │
│   Canvas（正方形寄り）   │
│                       │
├───────────────────────┤
│ [▶] [1x|4x|8x]  14:02/2:03:11 │
│ ─●━━◆━━◆━━━●─        │
│ [スタート][L1][L2][Fin]（横スクロール）│
├───────────────────────┤
│ ▾ 比較する2艇（折りたたみ） │
├───────────────────────┤
│ ▾ 反省メモ（折りたたみ・   │
│    タップで下からシート展開）│
└───────────────────────┘
```

- **DOM順は上図の通り「Canvas→再生コントロール→タイムライン→レグ→比較→メモ」が正**。モックアップ`replay.html`は「Canvas→比較・メモパネル→コントロール」の順で本仕様に反しており（56vhのCanvas直後にパネルが挟まり、スマホで再生ボタンが初期表示外に落ちる）、実装時はモックアップではなく本仕様に従う（§7 #2）。必要なら再生コントロールをsticky化してよい。
- 右サイドバーの2パネルは縦積みの折りたたみアコーディオンに変形（初期は閉）。着艇後の見返しでは「まず再生」が最優先のため、メモ/比較はデフォルト非表示で画面を圧迫しない。
- レグチップ行は横スクロール（navbar-row-bottomと同じ挙動）。
- タッチでのシークはタイムラインバーの直接ドラッグに加えて、Canvas上の左右スワイプでも±5秒シークできるようにする（プロジェクタ操作と違い、片手操作前提）。

## 5. 共有（部内URL／公開昇格／公開ビュー）

### 5.1 部内共有URL（画面ではなく状態）

新規画面は作らない。リプレイ画面が`?t=&boats=&leg=`を初期化時に読み、非メンバーには4.4の403状態を返す。挙動は4章に統合済み。

### 5.2 公開昇格ダイアログ（rev.5で追加・共有1）

```
│ だれが見られるか                                  │
│  ◉ リンクを知っている人だけ                       │
│    （URLを知る人は誰でも見られます・検索には出ません）│
│  ○ だれでも（検索にも出ます）                      │
│                                                  │
│ ⚠ 航跡の先頭・末尾に陸上の移動（自宅周辺など）が    │
│    含まれていないか確認してください                 │
│                                                  │
│                      [キャンセル]  [公開する]      │
└──────────────────────────────────────────────────┘
```

- **注釈チェックは既定で全オフ**。「全選択」ボタンは置かない（一括公開は事故の入口になるため、1件ずつ選ばせる摩擦を意図的に残す）
- 学びの要約が空、または401字以上のときは「公開する」をdisabled＋`.ds-field-hint--error`で理由表示（`alert()`は使わない＝§7 #6）
- 確定後: URLを自動コピーし、`role="status"` のトースト「公開しました。URLをコピーしました」
- 公開済みのヘッダは「**公開URLをコピー**」＋「公開をやめる」の2ボタンに変わる。「公開をやめる」は確認ステップを1つ挟み、**「公開URLは無効になります。もう一度公開すると新しいURLになります」**と明示する（PRD §5-2の1方向解釈）
- セッション一覧・リプレイ画面のヘッダに状態チップ（`公開中` / `リンク限定`）。非公開セッションには何も出さない

### 5.3 公開ビュー `/p/[slug]`（rev.5で追加・認証不要）

**DOM順が仕様**（スマホ縦画面でもこの順に積む）:

```
┌───────────────────────────────────────────────┐
│ sailvlog                          [これは何?] │
├───────────────────────────────────────────────┤
│ 江の島 定期練習 2026-07-20 ・ ○○大学ヨット部   │
│ ┌─ 学びの要約 ────────────────────────────┐ │
│ │ 上マーク回航後の展開が遅れる原因は…          │ │
│ └───────────────────────────────────────┘ │
├───────────────────────────────────────────────┤
│      Canvas（常時ダーク海図面・部内版と同一）    │
├───────────────────────────────────────────────┤
│ [▶] 速さ[1x][4x][8x]   00:14:02 / 02:03:11    │
│ ─●━━━━◆━━━━━━━━━━●─（公開注釈のみピン）    │
├───────────────────────────────────────────────┤
│ 公開されたメモ                                  │
│  00:14:02 ここのタックが早すぎた                │
├───────────────────────────────────────────────┤
│ sailvlog は大学ヨット部の反省会ツールです（説明）│
└───────────────────────────────────────────────┘
```

- **読み取り専用。編集系UIは一切描画しない**（メモ追加ボタン・公開ボタン・削除・比較チェックの保存等）。艇の表示切替と再生操作だけは残す（読む体験に必要なため）
- **ログイン導線を強制しない**。「これは何?」と最下部の説明ブロックのみ。「登録して続きを見る」は作らない（PRD §5・`SPEC-share1-phase1.md` §3.2）
- 海面は部内版と同じ常時ダーク（§0-1）。**再生エンジン（`lib/replay/`）はそのまま再利用し、描画コードを分岐も複製もしない**（ARCH ADR-007）
- 存在しない/非公開/取り消し済みのスラッグは**すべて同じ404画面**（「非公開です」と「存在しません」を区別しない＝総当たりの手がかりを与えない）
- OGP: `generateMetadata` で `title`（セッション名＋チーム名）・`description`（学びの要約の冒頭100字）・`og:image`（静的1枚）を出力。`リンクを知っている人だけ`のときは `robots: noindex`
- 閲覧数は**画面に出さない**（PRD §5-7 非KPI）

## 7. 実装時の必須修正（2026-07-25 UIレビュー3系統の指摘を仕様へ昇格）

モックアップに残存する既知の欠陥。**Next.js実装（TASKS.md T-13/T-14/T-15/T-25）ではこのリストを満たすことを完了条件に含める。**

1. **セッションカードのリンク化** — カード全体を`<Link>`で`/sessions/[id]`へ（モックアップは`article`のみでクリック不能＝主導線の欠落）。§2に反映済み
2. **モバイルDOM順** — 「Canvas→再生コントロール→タイムライン→レグ→比較→メモ」（§4.6が正。モックアップはコントロールが最下部）
3. **タイムラインのキーボード操作** — スクラブバーは`role="slider"`＋`aria-valuemin/max/now`＋矢印キー（±5秒、Shiftで±30秒）で操作可能にする。div+クリックのみは不可
4. **ファイル入力** — ドロップゾーンは`<button>`＋実`<input type="file">`。完全非表示のdisplay:noneではなく`.ds-visually-hidden`でフォーカス経路を残す
5. **フォームのlabel関連付け** — 全入力に`<label for>`（または`aria-label`）
6. **ステータス通知** — トースト・エラー帯に`role="status"`（重大なものは`aria-live="assertive"`）。`alert()`は使わない
7. **操作対象サイズ** — 注釈ピン等のタップ対象は最低24×24px（WCAG 2.2 Target Size。見た目10pxでも透明ヒット領域で拡張可）
8. **色以外の識別** — 6艇は色＋線種＋常時ラベルで識別（§4.2のルール）
9. **ダークテーマのコントラスト** — accent上の白文字が3.0:1しかない組（`--color-accent`ダーク値 #2f9fd1）は、16px級のボタン文言に使う場合4.5:1以上へ調整（文字色を暗色にする/accentを濃くする/大テキスト・太字19px以上に限定する、のいずれか。DSトークン側の修正はdesign-system更新として1コミットで行う）
10. **`<html lang="ja">`** — 現行フロントの`lang="en"`を修正
