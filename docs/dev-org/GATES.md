## ① Product Gate — 「作る価値があるか」 【人間承認必須】

- 担当: product-lead が PRD を提出 → **人間が GO/NO-GO**
- 入力: PRD.md（Product Review 6観点 + 競合3つ + MVP定義済み）
- 通過条件:
  - [x] PRD.md の DoD が全て✅
  - [x] 人間が「これは自分が使う/語れる」と確認した
- 通過記録: 2026-07-23 / 判定: **GO（条件付き・選択肢(c)）** / 備考: rev.3で承認。主役体験は即決せず、**2週間の並行検証**（A=Googleフォームでカード運用、E2=練習2回のスマホGPS収録+既製ツールで反省会1回）の計測結果で確定する。両方PASS→E2主役+A接続 / E2のみFAIL→A主役 / 両方FAIL→PRDへ差し戻し。検証と並行してarchitectの技術検証（GPX再生エンジンのスパイク）は先行してよい。経緯: rev.1(A推奨)→オーナーFBで差し戻し→rev.2(公開データ調査でE1不成立判明)→rev.3(6案公平比較・E2推奨)。

## 共有2の投稿モデルに関する裁定（オーナー 2026-08-01）— **PRD §5 の防波堤を1つ外す**

Issue #5（共有2の詳細設計）の設計方針として、オーナーが「Qiita のような形」を指示。分解すると3点。

| 要素 | 既存裁定との関係 | 扱い |
|---|---|---|
| 投稿を**プライベート**にできる | ✅ PRD rev.4「所有文脈 × public/followers/private の3択」と整合 | 確定 |
| 投稿時に**所属（個人 or チーム）を選べる** | ✅ 同裁定「アカウントは個人のみ＋チーム所属属性」と整合。Qiita の Organization に相当 | 確定 |
| **自由記述の記事を許す** | ❌ **PRD §5「自由記述は解禁しない」「自由記事の解禁は共有3で再判定」と正面衝突** | **裁定により解禁** |

**裁定内容**: 自由記述（Markdown本文）を基本とし、「セッティングカード」「練習/レース振り返り」は
**選べるテンプレート＝下書きの出発点**として提供する（フィールドの強制ではない）。
これは Qiita の実際の構造と同じで、型に収まらない知見（レース戦術・艤装・体づくり・代替わりの
引き継ぎ）も書けるようにするための判断。

### この裁定が外した防波堤と、その代わり（重要）

PRD §5 が自由記述を禁じた根拠は思いつきではなく実体験である —
**「供給源なき投稿箱は v1 が死んだ構造の再演」**。v1 は機能寄せ集めSNSとして供給が生まれず死んだ。
テンプレ限定は「何を書けばいいか分からない」を構造で回避する装置だった。

**その装置を1つ外す以上、代わりの検知手段を設計に持たせる**ことを architect への指示に含めた:
- テンプレートを「下書きの出発点」として提示するUIで、空の投稿画面問題にどう答えるか
- **失敗を早期に検知する計測の定義**（公開後Nヶ月で「オーナー以外の投稿者数」「自部以外からの投稿数」が
  閾値未満なら共有2は機能していないと判定する、といった具体値と観測方法）
- Qiita が成立するのは母数が大きく供給が個人の問題解決記録から自然発生するからであり、
  **部員10人規模で同じ力学が働く保証はない**。この非対称性に触れずに「Qiitaと同じにすれば動く」と
  書かせないこと

**PRD §5 の改訂手続き**: architect は仕様書内に改訂提案（置き換え文面＋理由）を書くのみ。
**実際の PRD 改訂は Team Lead / product-lead が行う。** 防波堤を外す変更を設計工程の副作用として
静かに通さないため、改訂は独立した工程として扱う。
