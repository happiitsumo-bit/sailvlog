## 目的

主役候補 A（セッティングカード図鑑）と E2（反省会リプレイ・デバッガ）の最大リスク仮説「**データ供給が続くか**」を、コード0行・費用0円・2週間で計測し、主役決定の証拠を得る。

## 検証A: カード図鑑（Googleフォーム運用）

**仮説**: 部員は着艇後2〜3分でセッティングカードを書き、週2枚×数名が2週間続く。

**手順**:
1. Googleフォームを下のスキーマで作成（回答先スプレッドシート）
2. 部のLINE/Slackに固定リンクを掲示。「着艇後の片付け中に1枚」とだけ依頼（リマインドは週1回まで — 強く催促した数字は本番の予測にならない）
3. 2週間後にスプレッドシートを集計

**フォーム項目案（470用・叩き台。部の呼び方に合わせて修正してよいが、項目の追加は慎重に — 増やすほど書かれなくなる）**:

| 項目 | 形式 |
|---|---|
| 日付・練習/レース | 日付+選択 |
| 風速帯 | 選択: 〜4kt / 4〜8 / 8〜12 / 12〜16 / 16kt〜 |
| 海面 | 選択: フラット / チョッピー / うねり |
| 乗員合計体重 | 数値（kg、任意） |
| マストレーキ / シュラウドテンション | 短文（ピン位置・数値など普段の表現で） |
| ジブハリ・カニンガム・アウトホール・バング | 短文各1 |
| 今日の一言（何が効いた/効かなかった） | 長文1つ |
| 手応え | 選択: 走った / 普通 / 走らなかった |
| 写真（任意） | ファイル添付 |

ILCA用は別フォーム（バング/カニンガム/アウトホール中心）。**2艇種以上に増やさない**。

**計測（スプレッドシートに週次で記録）**:
- 提出枚数 / 週、提出者のユニーク数、1枚の記入所要時間（フォームのタイムスタンプ間隔or本人申告）
- 空欄率の高い項目（→本実装でスキーマから削る候補）

**合格ライン**: 2週間で計10枚以上 かつ 提出者3名以上 かつ 2週目が1週目の半分を下回らない。

## 検証E2: リプレイ（スマホ収録→既製ツールで反省会）

**仮説**: マネ艇/部員のスマホで航跡が録れ、反省会でリプレイを見ると議論が変わる。

**手順**:
1. 収録アプリを各艇+マネ艇のスマホに入れる（無料GPSロガー。GPX形式でエクスポートできること・バックグラウンド動作・記録間隔1〜2秒設定を事前に艇庫で動作確認）
2. 練習2回で収録: 出艇前に録画開始→防水ケースで艇内固定→帰着後にGPXエクスポートして共有フォルダへ（この手順の「面倒くささ」自体が計測対象）
3. リプレイツールで再生: 第一候補 **[TackTracker](https://tacktracker.com/web/)**（Garmin GPX等のインポートと複数艇リプレイに対応）。フォールバック: [raceQs](https://raceqs.com/faq/creating-and-managing-tracks/)のGPXアップロード（[フォーラムで動作不安定の報告あり](https://raceqs.com/forum/topic/gpx-file-uploads/)のため第一候補にしない）
4. 反省会を1回、リプレイを映しながら実施

**計測**:
- 収録成功率（艇×練習回のうちGPXが取れた割合）と失敗理由（録り忘れ/電池/防水/操作）
- GPS精度: タックの位置・タイミングが議論に耐えるか（航跡がジグザグに暴れないか）— 主観でよいが部員2名以上に聞く
- 反省会の変化: リプレイを見て初めて出た論点がいくつあったか（ホワイトボードだけでは出なかった発言を数える）
- アップロード所要時間（帰着→共有完了まで）

**合格ライン**: 収録成功率60%以上 かつ 精度が「議論に耐える」評価 かつ 反省会で新規論点3つ以上。

## 判定マトリクス（2週間後）

| A | E2 | 主役決定 |
|---|---|---|
| PASS | PASS | **E2主役 + Phase 2でA接続**（PRD rev.3推奨どおり） |
| FAIL | PASS | E2主役（Aの接続は再設計後に再検証） |
| PASS | FAIL | A主役（rev.1スコープに差し替え） |
| FAIL | FAIL | PRDへ差し戻し（仮説が両方外れたら実装しないのが正解） |

## 同時にやる小タスク

- **TracTrac KML有効イベント探索（1日だけ）**: 470/ILCAの過去イベントでKML Downloadが有効なものを探す。見つかればE2のシード教材、見つからなくてもMVPに影響なし（PRD §7 第3リスク）
  - **初期調査結果（2026-07-24）**: KML出力は主催者がイベント単位で有効化する仕組みで、主に[Njord連携用](https://www.sailnjord.com/data-sources/tractrac/)。[ILCA UKの各イベント](https://tractrac.com/event-page/event_20251009_ILCAUKNati/3373)等でリプレイ閲覧は恒久公開されているが、**第三者が自由にKMLダウンロードできる470/ILCAイベントは今回の探索では未発見**。現実的な入手経路は「主催者に直接依頼」。→ シード教材は自部収録データを主とする前提を強める材料
- **案Fヒアリング（オーナー→部員へ、5分）**: 「上手い人のタック動画、今どこで見てる? 部のInstagram/LINEで足りてる? 誰が撮る?」— Fの既存代替の強さを一次情報で確認

## オーナーレビュー時の確認事項（PRD rev.3 §9 と対応）

1. 主役の判定: (a) E2でGO（推奨） / (b) AでGO / (c) この並行検証の結果で決める / (d) F再検討 / (e) NO-GO
2. 検証Aのフォーム項目: 470の項目名は部の呼び方と合っているか（上の叩き台を添削してほしい）
3. 検証E2の体制: 録る係は誰か（マネ艇1名で足りるか、各艇スマホも載せるか）
4. 8週間の計測期間が取れるシーズン日程はいつか（PRD §6の前提）
