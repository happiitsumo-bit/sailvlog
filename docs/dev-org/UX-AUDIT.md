# UX-AUDIT — sailvlog

- 監査日: 2026-08-02
- 監査者: UX Reviewer（初見の第三者として実施。監査本体を書き終えるまで `docs/dev-org/` と `README.md` は一切読んでいない）
- 対象: ローカル開発環境 `http://localhost:3001`（backend `:8001`、docker compose 稼働中）／本番 `https://sailvlog.vercel.app`（閲覧のみ）
- 環境: macOS 15.5 / Chrome 150（専用プロファイルを新規作成した完全未ログイン状態）/ CDP経由で実操作
  - デスクトップ: 1280x800（一部 1280x625 実効ビューポート）
  - モバイル: `Emulation.setDeviceMetricsOverride` で 390x844 / DPR2 / touch有効
- 操作記録: 全ステップをスクリプト実行ログ＋スクリーンショット34枚で記録（`/private/tmp/.../scratchpad/shots/`）
- **コードは一切変更していない。** DBへの介入は後述 B-1 の回避のため `TeamMember` に1行 INSERT したのみ（ローカル開発DB）

## 1. 10秒テスト（最初の10秒で受け取ったもの・後から書き換えていない生の印象）

未ログインで `http://localhost:3001/` を開いて10秒。

> 「ヨットのGPSログを重ねて再生するツールらしい。画面の真ん中に、色分けされた線が何本か走っている暗い図が出ている。ただ **これは地図に見えない** — 海岸線も陸地も無く、青いグラデーションの上に線が引いてあるだけなので、どこを走っているのかは分からない。
> 『デバッガ』という言葉が引っかかる。プログラムのデバッグツールかと一瞬思った。
> 押せそうなボタンは右上の Login / Join と、真ん中の『ログイン』『収録ハンドブックを読む』だけ。**触って試せる入口が見当たらない。** ログインしないと何も始まらないタイプのサービスだと理解した。
> 『マネ艇』という語が図の中にあるが、これが何かは分からない（ヨット用語なら通じるのだろう）。」

10秒後の一言まとめ: **「ヨット部が練習の航跡を並べて見返すための、ログイン必須の内輪ツール」**

作り手への含意（ここは10秒時点の印象ではなく、その解釈）:
- 「何をするアプリか」は10秒で伝わっている。**コンセプト伝達は成功している。**
- 一方で「自分が触れるもの」が10秒以内に1つも見つからない。ヒーロー画像がスクリーンショットの静止画で、押せるものではない。

## 2. First Run（初見ユーザーの通し操作）実測

やったこと: 未ログイン → 登録 → ログイン → チーム作成 → GPX取込 → 再生 → 注釈 → 公開 → 公開ページ閲覧。

| 項目 | 実測 | 評価 |
|---|---|---|
| セットアップ所要（登録フォーム到達→アカウント作成完了） | 入力3項目、クリックから `/sessions` 到達まで 3秒以内（APIは1秒未満） | 良好 |
| **初回価値到達（自分のデータでリプレイが動くまで）** | **到達不可能。** UI上にチームを作る／参加する導線が存在しない（後述 B-1） | **失格** |
| 初回価値到達（回避策でチームに所属させた後） | Sessions → チーム選択 → セッション選択 → **700pxスクロール** → 再生 = 4クリック＋1スクロール | 許容範囲だが、地図に辿り着くのにスクロールが必須なのは損 |
| GPX解析（6艇 × 各7200点）→ プレビュー描画 | 体感0.3秒未満（待ちを感じない） | **優秀** |
| 取込保存 → 一覧へ遷移 | 0.6秒未満 | 優秀 |
| セッション詳細のページ表示 | FCP 84ms / load 203ms / `GET /api/sessions/2` 57ms | 優秀（ローカル） |
| 本番ランディング | TTFB 35ms / load 297ms | 優秀 |

### 手が止まった箇所・推測が必要になった箇所（逐次記録）

1. **登録直後**（`/sessions`）: 「チームを選択」のドロップダウンに **選択肢がゼロ**。空状態の文言は「チームを選択するとセッション一覧が表示されます」だけで、チームの作り方は書いていない。ここで完全に止まった。
2. `+ Import GPX` を押せば何か始まるかと**推測**して進んだ → `TEAM *`（必須）のドロップダウンも空。手詰まり。
3. `/teams` というURLがあるのではと**推測**して直打ち → **404**。
4. `収録ハンドブック` を読んだ（唯一のヘルプ）→ 「タイトル・チーム…を入力」とあるだけで、**チームの入手方法はどこにも書かれていない**。
5. ここで初見ユーザーとしては詰み。監査続行のため、APIを直叩き（`POST /api/teams`）→ **500 Internal Server Error**（原因は後述）。最終手段としてDBに `TeamMember` を1行入れて先へ進んだ。
6. チーム所属後も、`Sessions` に来るたびに毎回チームを選び直す必要がある（1件しかなくても自動選択されない）。
7. セッションを開くと、最初に目に入るのは「航跡を追加」のアップロードカード。**地図（このアプリの本体）は画面外**。スクロールして初めて出会う。
8. 再生開始直後（t=0）は全艇がスタートライン上で重なり、ラベルが `4123マネ艇` のような判読不能な塊になる。「壊れているのか？」と一瞬思った（実際は正常。時間が進めば散る）。
9. 地図をホイールで拡大しようとしたが**無反応**。ドラッグでの移動も**無反応**。艇は画面の右上1/10ほどの領域に小さく描かれたまま。
10. 公開しようとしたが、自分（member権限・アップロード者でない）には「公開する」ボタンが出ない。これは権限設計として妥当だが、**「なぜ出ないのか」の説明は画面上に一切ない**。自分でGPXを取り込んでアップロード者になって初めてボタンが出た。
11. 公開ダイアログを開いた瞬間、まだ何も入力していないのに「学びの要約は必須です」というエラーが既に表示されている。「もう間違えた？」と感じた。
12. そのダイアログの「公開する」「キャンセル」ボタンが**初期表示では画面外**（ダイアログ高さ=ビューポート高、確定ボタンは y=765 / ビューポート 625）。ダイアログ内をスクロールして探す必要があった。

## 3. 指摘一覧

### Blocker（これがあると人に見せられない）

#### B-1. 新規ユーザーはチームを作れず、永遠に価値へ到達できない
- **どこで**: 登録直後の `/sessions`、および `/sessions/new` の `TEAM *`
- **何が起きたか**: 新規アカウントの所属チームは0件。UI全体を探しても「チームを作る」「招待コードで参加」に相当するボタン・リンク・ページが存在しない（`/teams` は404）。セッション取込は `TEAM *` が必須なので、GPXを1本も取り込めない。ハンドブックにも入手方法の記載なし。
  - 追加事実: バックエンドには `POST /api/teams` と `POST /api/teams/join`（招待コード）が実装されているのに、フロントエンドから呼ぶ画面が無い（`frontend/src` に `招待` / `inviteCode` / `teams/join` の参照ゼロ）。**機能はあるがUIが無い**状態。
  - さらに、**現在起動中のローカル環境では `POST /api/teams` 自体が500で落ちる**。ログ: `Unknown argument 'inviteCode'`（`backend/src/routes/teams.ts:197`）。DBにもschema.prismaにも `inviteCode` 列はあるので、**動いているコンテナのPrismaクライアントが古い**（マイグレーション後に再生成されていない）。→ 「デモ直前に `docker compose up` した環境で、チーム作成が500になる」状態が現に起きている。
- **初見の人がどう受け取るか**: 「登録したのに何もできない。使い方が分からないのか、壊れているのか判断がつかない」。デモで「じゃあ登録から見せます」と言った瞬間に終わる。
- **改善案**:
  1. 空状態に「チームを作る」ボタンを置く（名前を入れるだけ、slugは自動生成でよい）。「招待コードで参加」も併置。
  2. `/sessions/new` の `TEAM *` が空のときは「所属チームがありません → チームを作る」を選択肢の位置に出す。
  3. 起動中コンテナの `prisma generate` 不整合を解消し、**チーム作成のE2E（登録→チーム作成→取込）を1本テストで固定**する。今このパスを守るテストが無いから500に気づけていない。
- **再現手順**: 未ログインで `/register` → 任意のアカウント作成 → `/sessions` のドロップダウンを開く（選択肢なし）→ `+ Import GPX` → `TEAM *` を開く（選択肢なし）→ `/teams` を直打ち（404）。

#### B-2. モバイル幅でヘッダのボタンが縦1文字ずつに崩れ、本文に覆いかぶさる
- **どこで**: 390x844。ログイン後の**全ページ**のヘッダ（`公開ページを見る`）
- **何が起きたか**: ボタンが幅52px・高さ206pxに潰れ、「ー / ジ / を / 見 / る」と縦積みになり、ヘッダの外（y=-77、つまりヘッダ上端より上）へはみ出して、`Sessions` の見出しや地図の上に白い箱として重なる。
- **初見の人がどう受け取るか**: 「作りかけのページを踏んだ」。スマホで開いた部員は、まずこの崩れを見る。
- **改善案**: ヘッダを `flex-wrap` + `min-width:0` で組み直す。狭幅では文言を「公開ページ」または アイコンのみに短縮するか、ハンバーガー／下部タブ（既にある）へ寄せる。
- **再現手順**: DevToolsデバイスモード 390x844 → ログイン状態で `/sessions` または `/sessions/4` を開く。
- **証拠**: `shots/50-m-landing.png` `52-m-session.png` `53-m-session-map.png` `60-broken-gpx.png`（4画面すべてで再現）

#### B-3. 本番に「動いているところ」を見せる導線が1本も無い
- **どこで**: `https://sailvlog.vercel.app/`
- **何が起きたか**: 本番ランディングのリンクは `ログイン` / `収録ハンドブックを読む` / `GitHubリポジトリ` のみ。読み取り専用の公開セッション（`/p/[slug]`）は実装済みで、まさにこの用途に使えるのに、**サンプルへのリンクが1つも置かれていない**。データもほぼ空。
- **初見の人がどう受け取るか**: SNS・面接経由で来た人（＝アカウントを作る動機がない人）は、**このプロダクトが動く様子を1秒も見られずに離脱する**。README/GitHubを開く人だけが救われる。
- **改善案**: デモ用チームの1セッションを `public` で公開し、ランディングの主CTAを「デモを見る（ログイン不要）」にする。現在の主CTA「ログイン」は既存ユーザー向けで、初見への提案になっていない。
- **なぜBlockerか**: このプロダクトの目的の一つが「人に見せる」ことである以上、"見せられない本番" は主要経路の欠落と同じ。好みの問題ではない。

### Major（初見ユーザーが迷う・誤解する）

#### M-1. ダークモードで枠線ボタンの輪郭が消える
- **どこで**: OSがダークモードのときの全画面。`現在位置を次のレグ開始にする` / `編集` / `共有URLをコピー` / `GPXを選択` / `公開ページを見る` など枠線ボタン全般。
- **何が起きたか**: 実測で `background: rgba(0,0,0,0)`、`border: 1px solid rgba(28,28,31,0.28)`、`body背景: rgb(0,0,0)`。**黒地に黒枠**でコントラスト比ほぼ1:1。ボタンが「ただのテキスト」に見える。
- **初見の人がどう受け取るか**: 「押せるのかどうか分からない」。夜にデモすると全ボタンが平坦に見える。
- **改善案**: `--border` をダーク用に反転（例 `rgba(255,255,255,0.24)`）。デザイントークンのダーク定義漏れなので1箇所で直せるはず。
- **再現手順**: macOSを夜間モード/ダーク外観にして任意のページを開く。`getComputedStyle` で上記値を確認。

#### M-2. セッション詳細の第一画面に地図が無い
- **どこで**: `/sessions/[id]`
- **何が起きたか**: 1280x800でもファーストビューはタイトル＋「航跡を追加」（GPXアップロード）カードで埋まり、地図は700pxスクロールしないと現れない。
- **初見の人がどう受け取るか**: 反省会で画面を出した瞬間に映るのが「ファイルアップロード欄」。**このプロダクトで一番の見せ場が初期表示に無い。**
- **改善案**: 「航跡を追加」を折りたたみ（`details`）か地図の下へ移動し、地図＋再生バーをファーストビューに固定する。

#### M-3. チーム選択が保持されない／1件でも自動選択されない
- **どこで**: `/sessions`
- **何が起きたか**: 所属チームが1件でもプレースホルダ「チームを選択」のまま。選択して一覧を見た後、他ページから戻ると再びリセット（`?teamId=3` を持っていても表示状態は初期化される場面あり）。
- **初見の人がどう受け取るか**: 「毎回同じ操作をさせられる」。部員は毎回同じチームしか選ばない。
- **改善案**: チームが1件なら自動選択。複数なら直近選択を localStorage に保持。

#### M-4. 深いリンクからログインすると、元のページに戻らない
- **どこで**: 未ログインで `/sessions/2` を開く → `/login` へリダイレクト → ログイン後 `/sessions` へ着地（しかもチーム未選択の空状態）。
- **初見の人がどう受け取るか**: 「送ってもらったリンクを開いたのに、目的のセッションが消えた」。反省会前にURLをLINEで共有する運用（ハンドブックが推奨している運用そのもの）と正面衝突する。
- **改善案**: `/login?next=/sessions/2` を付与し、ログイン後に復帰。

#### M-5. t=0 で全艇が重なり、ラベルが判読不能な塊になる
- **どこで**: リプレイ地図（社内・公開ページ両方）の再生開始前
- **何が起きたか**: 6艇がスタート地点に重なり、常時ラベルが重畳して `4123マネ艇` / `b:b:o boat6_s...` のような黒い塊になる。**公開ページを開いた部外者が最初に見る絵がこれ。**
- **改善案**: ラベルの衝突回避（重なったら代表1つ＋「+3」表記、または引き出し線）。もしくは初期時刻を「全艇が散開した最初の時刻」にするか、静止時はラベルを非表示にして航跡だけ見せる。
- **証拠**: `shots/16-replay-map.png`（社内） `42-public-playing.png`（公開）

#### M-6. 地図の拡大・縮小・移動ができない
- **どこで**: リプレイ地図
- **何が起きたか**: canvas上でホイール（`WheelEvent`）・ドラッグ（PointerEvent）を送っても描画は不変（スクリーンショットのハッシュが完全一致）。コード上も `wheel` / `zoom` ハンドラは存在しない。結果、艇はキャンバスの一部に小さく描かれ、画面の6〜7割は空の青。
- **初見の人がどう受け取るか**: 「マーク際の競り合いを拡大して見たい」ができない。反省会の主目的（タックの位置とタイミングの議論）に直撃する。
- **改善案**: 最低限「ホイールでズーム＋ドラッグでパン」。次点で「選択2艇にフィット」ボタン。
- **専門知識の留保**: 背景地図（海図・海岸線）が無いことについては、意図的な設計（オフライン/タイル費用/艇の相対位置だけ見ればよい）の可能性があるため**判断保留**。ただし初見には「地図が読み込まれていない」に見える、という事実は記録しておく。

#### M-7. 公開ダイアログの確定ボタンが初期表示で見えない
- **どこで**: セッション詳細 →「公開する」
- **何が起きたか**: ダイアログ高さ=ビューポート高（625px）、`overflow:auto`。`公開する`/`キャンセル` は y=765 にあり画面外。開いた直後は「学びの要約は必須です」という**先制エラー**だけが目に入る。
- **初見の人がどう受け取るか**: 「エラーが出ていて、決定ボタンも無い」＝ 詰まったと勘違いする。
- **改善案**: フッター（キャンセル／公開する）をダイアログ内で固定表示（sticky）にする。バリデーションエラーは初回のsubmit試行後に出す。

#### M-8. 反省メモの入力欄が1行の `<input>`（最大2000文字）
- **どこで**: セッション詳細 右下「現在時刻(hh:mm:ss)に議論を残す」
- **何が起きたか**: 1500文字入れても1行のまま。入力中の文章を読み返せない。公開ダイアログの「学びの要約」には文字数カウンタ（0/400）があるのに、こちらには無い。
- **改善案**: `textarea`（2〜4行、自動拡張）＋文字数カウンタ。

#### M-9. 「共有URLをコピー」と「公開URLをコピー」が同一画面に並ぶ
- **どこで**: 公開済みセッション詳細。ヘッダ下に `公開URLをコピー` `公開をやめる`、再生バー横に `共有URLをコピー`。
- **何が起きたか**: どちらが部外に出るURLか、ラベルからは区別できない（未公開状態でも `共有URLをコピー` は常に押せる）。公開/非公開の取り違えは**事故の方向が怖い**種類のミス。
- **改善案**: 前者を「公開リンク（部外可）をコピー」、後者を「部内リンクをコピー」に改名。未公開時は前者を非表示、後者に「部内のみ」バッジ。

### Minor（磨けばもっと良くなる）

- **m-1**: 登録フォームにパスワード要件（8文字以上）が事前に書かれていない。失敗して初めてブラウザ標準の吹き出しで知る。→ ラベル横に「8文字以上」。
- **m-2**: ランディング「できること」の4枚のスクリーンショットが小さすぎて、中の文字が一切読めない（デバイスフレーム込みで幅約440px相当に4枚並列）。装飾にはなっているが情報を伝えていない。→ 2枚×2段に拡大、またはGIF/動画1本に置換。
- **m-3**: 取込フォームでファイルを選んでも画面上部は無反応。ファイル一覧とプレビューは画面外に増える。→ 選択後にプレビューへスクロール、または件数を上部に出す。
- **m-4**: 取込プレビューは**白背景**、実際の再生画面は**濃紺背景**。同じデータが別物に見える。→ プレビューも本番と同じ配色に。
- **m-5**: 艇ラベルの初期値がファイル名（`boat1_clean`）。編集しないとそのまま公開ページに出る。→ 「未編集のラベルがあります」の注意、またはセール番号の入力を促すプレースホルダ。
- **m-6**: 壊れたGPXのエラーメッセージが**青文字**（リンク色と同じ）。警告に見えない。→ 赤系＋アイコン。
- **m-7**: 空状態のアイコンが線だけの「○」で、ローディングスピナーに見える（実際に一瞬「まだ読み込み中か？」と待った）。→ 意味のあるイラスト/アイコンに。
- **m-8**: 取込完了後、作ったセッションではなく一覧へ戻される。→ 作成したセッションへ直行（作った本人はすぐ再生を見たい）。
- **m-9**: 左カラム（レグカードの下）に数百pxの空白が残り、右カラムだけが長い。→ 2カラムの高さバランス調整。
- **m-10**: ヘッダは `Login` / `Join`（英語）、本文は日本語、`Sessions` `Import GPX` も英語。下部タブは絵文字アイコン（⛵📘）。**言語とアイコンの粒度が混在**していて、細部の詰めが甘く見える。

## 4. 良かった点（根拠つき）

- **公開昇格ダイアログの設計が、この規模の個人開発として明確に水準以上。** 「学びの要約（必須・400字カウンタ付き）」「メモは既定で非公開、選んだものだけ公開」「リンク限定 / だれでも の明示的な選択」「航跡の先頭・末尾に自宅周辺が含まれていないか確認してください」という**プライバシー警告**まで入っている。公開ページの `<meta name="robots" content="noindex, nofollow">` も実際に出力されていた（実測）。「部外に出す」ことの怖さを理解して作られている。
- **壊れたGPXの扱いが丁寧。** 不正XMLと trkpt 0件を別メッセージで**ファイルごとに**表示し、正常な1本は残したまま `取り込む` を disabled にする。「エラーが出たファイルだけ外してやり直す」というハンドブックの記述と実装が一致している。
- **注釈まわりの操作感が良い。** メモをクリックすると再生位置がその時刻へジャンプ（00:10:14 → 00:54:34 を実測）、投稿フォームの見出しが「現在時刻(00:54:34)に議論を残す」と追従、追加は即時に時刻順へ挿入。モーダルを開かない設計が効いている。
- **コピー操作のフィードバックが明確。** ボタン文言が「共有URLをコピー」→「URLをコピーしました」に変化。公開時は「公開しました。URLをコピーしました」。
- **エラー・権限まわりの文言と復帰導線が整っている。** 404は「the wind took it somewhere else」＋Back to Home、他人のセッションは「閲覧できません／セッションが見つかりません」＋Sessionsへ戻る。未ログインでの保護ページは確実に `/login` へ。**認可は期待通りに効いていた。**
- **収録ハンドブックが実務的。** Geo Trackerの記録間隔、位置情報を「常に許可」、低電力OFF、試し録り、ファイル名規約、そして**無料ホスティングのcold startを見越して「反省会の直前に一度開いておく」**まで書いてある。作り手が現場を知っていることが伝わる、このプロダクトで一番好感の持てるページ。
- **性能は文句なし。** 6艇×7200点のGPXをクライアントで解析してプレビュー描画まで体感0.3秒未満、保存0.6秒未満、詳細ページFCP 84ms。「待たされて不安になる場面」はローカルでは1つも無かった。
- **壊しにいっても壊れない。** 再生ボタン12連打・速度ボタン20回トグル・1500文字入力・不正ファイル混在のいずれでもコンソールエラー0件、状態の破綻なし。

1. **開始位置を t≒10分にしてから画面を出す**（t=0の重なりを見せない）。1x再生で数秒流す。

- t=0のリプレイ画面（ラベルが塊）

## 付録C. 作り手の意図（PRD）と、初見の自分が受け取ったもののズレ

**※ここは監査の本体ではない。上記すべてを書き終えた後に `PRD.md`（rev.7）を初めて読み、差分だけを追記したもの。**

### C-1. 「ミッションが伝わっていない」— PRD側の最大の関心事に、初見は一度も触れなかった

PRD §1（rev.7）はミッションを **「ヨットの知識等を共有して、埋もれさせない」** と明文化し、「ブランド・公開面のコピーは特定機能（『反省会』『リプレイ』）ではなくミッションに紐づける」と明記している。

初見の私が10秒で受け取ったのは **「ヨット部が練習の航跡を並べて見返すための、ログイン必須の内輪ツール」** で、*知が代替わりで失われる／それを残す* という主題は最後まで一度も受け取っていない。ランディングのコピーは「大学ヨット部の反省会のための、複数艇GPXリプレイ・デバッガ」＝**機能名そのもの**であり、rev.7が「そうしない」と決めた書き方のままになっている。文書は更新されたが公開面は追随していない。

- 影響: 部外者（＝ミッションの受け手）に届く唯一の面が、内輪の道具の説明になっている。
- 提案: ヒーローの1行を「代で消えるヨットの知を、航跡と一緒に残す」系へ寄せ、機能説明（複数艇GPXリプレイ）はその下のサブコピーへ落とす。ただしPRDの下限「**ヨットのアプリだと分かること**」は現状すでに満たせているので、そこは壊さないこと。

### C-2. 「デバッガ」というメタファーは、意図どおりには伝わっていない

PRD §4は「デバッグのように」を主役体験の核に据え、①スクラブ再生=ステップ実行 ②2艇比較=変数ウォッチ ③レグ頭出し=ブレークポイント ④注釈=issue ⑤URL共有=PRレビュー、というUX翻訳まで設計している。**この5つは実装されている**（私は②③④⑤を実際に操作して確認した）。

しかし初見の私は「デバッガ」を見て「プログラムのデバッグツールか？」と一瞬混乱しただけで、この5点セットの意図には気づかなかった。5つが**画面上でバラバラに置かれている**ためだ（レグは中段のカード、比較は右カラム中ほど、注釈は右下、共有は再生バー横）。意図が強いのに、UIがその意図を語っていない。

- 提案: デモでも画面でも、①→②→③→④の順に触らせる導線（初回オンボーディングのチェックリスト等）があると、設計意図が初見にも伝わる。ヨット部員（＝非プログラマ）には「デバッガ」という語自体が刺さらない可能性もあり、そこはターゲット判断。

### C-3. B-1（チームを作れない）は、PRD上「作らない」と決めた結果ではない

PRD §5の「明示的に入れない」にチーム作成UIは含まれていない。§5-6の共有層要件でも「チームはエンティティとして存在」「Team/TeamMemberはv1資産を活かす」とされており、**チーム作成は前提として扱われている**（v1から存在する想定）。つまりB-1は仕様上の意図的な省略ではなく、**v3で画面を作り直したときに落ちた抜け**と読むのが自然。私が監査中に見つけたAPI（`POST /api/teams` / `/api/teams/join`）の存在もそれを裏づける。→ B-1の指摘は取り下げない。むしろ「意図せず落ちている」ので優先度は上がる。

### C-4. B-3（本番に見せるものが無い）は、PRDの成功指標と正面から食い違う

PRD §6の共有1→共有2の前進条件は **「部外からの閲覧が実際に発生（publicViewCount > 0 が3本以上、他大学関係者への公開URL実送付2件以上）」**。つまり *部外の人が公開ページを見る* ことが計測の中心に置かれている。にもかかわらず本番には公開セッションが1本も無く、ランディングから公開ページへ至る導線も無い。**指標を満たしようがない状態**で本番が置かれている。B-3は「見栄えの問題」ではなく「PRDが定めた計測が回らない」問題として扱うべき。

### D-1. B-1（チーム作成UIが無い）— **確認。ただし500の因果は監査と異なる**
