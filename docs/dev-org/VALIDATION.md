## 1. A検証キット — セッティングカード（Googleフォーム運用）

### 1-1. Googleフォーム設問（コピペで作成可・全12問・目標入力時間2〜3分）

フォーム名: **「今日のセッティングカード（470）」**
説明文: 「着艇後、記憶が新しいうちに1艇1枚。2〜3分で終わります。わからない項目は空欄でOK。」

**項目数上限は12問**とする（これ以上足さない。追加したくなったら既存を1つ削る）。選択式を優先し、自由記述は2問だけ。**検証は470のみ**（ILCA用の別フォームは作らない — 艇種を増やすと計測が濁る）。

| # | 設問 | 形式 | 必須 |
|---|---|---|---|
| 1 | 日付・区分（練習/レース） | 日付+選択 | 必須 |
| 2 | スキッパー/クルー（記入者名でも可） | 短文 | 必須 |
| 3 | 風速帯 | 選択: 〜4kt / 4〜7kt / 7〜12kt / 12〜16kt / 16kt〜 | 必須 |
| 4 | 海面 | 選択: フラット / チョッピー / うねり / 混在 | 必須 |
| 5 | ペア合計体重 | 選択: 〜110kg / 110〜120kg / 120〜130kg / 130kg〜 | 必須 |
| 6 | サイドステーのテンション（ゲージ値 or ピン段数。例「28 / 上から3」） | 短文 | 必須 |
| 7 | ジブリード位置（例「基準から後ろ1穴」） | 短文 | 任意 |
| 8 | カニンガム | 選択: 引かない / 軽く / 中 / 強く | 任意 |
| 9 | アウトホール | 選択: 緩め / 基準 / 引き気味 / 最大 | 任意 |
| 10 | バング | 選択: 緩め / 基準 / 引き気味 / 強く | 任意 |
| 11 | 今日の一言（何を変えて→どうなった。1〜2文） | 長文 | 必須 |
| 12 | 手応え | 選択: ◎走った / ○普通 / △合わなかった / ？わからない | 必須 |

- 必須は8問。リグ詳細（7〜10）を任意にするのは「空欄でも1枚は成立する」ため。**空欄率そのものが計測対象**（どの項目が現場で書かれないかを知るのが目的の半分）。
- 写真添付（任意）を入れたい場合は#8〜10のどれかと**入れ替え**る（上限12問は維持。図鑑化したとき写真の価値は高いので、部で撮る習慣が既にあるなら入れ替え推奨）。
- **オーナー確認**: ①サイドステーの部内での通用表現（ゲージ値か段数か）②マストレーキ/マストステップ位置を項目に入れるべきか（毎練習で変える部なら#7と入れ替え。シーズン固定なら入れない）③ジブハリテンションをサイドステーと別項目にすべきか。**入れ替えはOK、総数12問は超えない**こと。

### 1-2. 部員への依頼文テンプレ（LINEにそのまま貼る）

> 【お願い・2週間だけ】セッティングの記録実験をします。
> 着艇したらこのフォームに1艇1枚だけ入力してください → （フォームURL）
> 2〜3分で終わります。わからない項目は空欄でOK。
> 「今日の風にどう合わせて、走ったか」が2週間でどれだけ貯まるか試したいです。
> 貯まったら風速帯ごとに一覧にして共有します。次の練習からよろしく！

（ポイント: 期限明示・所要時間明示・見返りの提示。リマインドは練習日の着艇時刻ごろにオーナーが一言送る。**リマインドは1練習1回まで** — 強く催促して集めた数字は本番の予測にならない。それ以上必要なら「習慣にならない」というデータとして扱う）

## 2. E2検証キット — リプレイ（スマホGPS収録 + 既製ツール反省会）

### 2-1. 収録アプリの選定

比較した候補（条件: iOS/Android両対応・無料・GPX出力・バックグラウンド記録）:

| 候補 | 両OS | 無料 | GPX出力 | バックグラウンド | 備考 |
|---|---|---|---|---|---|
| **Geo Tracker**（[FAQ](https://geo-tracker.org/en/faq/) / [iOS版](https://apps.apple.com/us/app/geo-tracker-gps-tracker/id1610586137)） | ✅ | ✅ | ✅ GPX/KML | ✅ | **推奨**。記録間隔を細かく設定可 |
| [ルートヒストリー](https://www.ateow.com/?page_id=687)（[iOS](https://apps.apple.com/jp/app/%E3%83%AB%E3%83%BC%E3%83%88%E3%83%92%E3%82%B9%E3%83%88%E3%83%AA%E3%83%BC-gps%E3%83%AD%E3%82%AC%E3%83%BC%E3%82%A2%E3%83%97%E3%83%AA/id1473949280)） | ✅ | ✅ | ✅ | ✅ | 日本語で扱いやすいが**最短記録間隔が5秒**（[設定解説](https://www.skiss.com/blog/2026/route_history202603/)）。5秒間隔=5ktで約13m進む。タック議論には粗い可能性 |
| [Open GPX Tracker](http://www.merlos.org/iOS-Open-GPX-Tracker/) | ✕ 実質iOSのみ | ✅ OSS | ✅ | ✅ | 1秒間隔可・広告なし。iOS勢の代替 |

**推奨: Geo Tracker、記録間隔は最短（1〜2秒）に設定。** ただし記録間隔の実挙動は端末依存のため、**Day 0の陸上リハーサル（§2-2冒頭）で必ず確認**する。1秒級が出なければ iOS=Open GPX Tracker / Android=Geo Tracker のOS別構成に切り替える。

### 2-2. 収録手順書（マネ艇・救助艇担当にこのまま渡す）

**Day 0（練習前日まで・陸上リハ 45分）** — オーナー実施:
1. 収録に使うスマホ2〜4台（乗艇する部員のスマホでよい）に Geo Tracker を入れ、記録間隔を最短に設定・位置情報の許可を「常に許可」にする
2. 自転車か徒歩で5分録る → GPXを書き出す → §2-3の再生ツール**両方**（raceQs / TackTracker）に通して再生できることを確認し、**動いた方を反省会ツールに確定**する。**海に出る前にパイプ全体を一度通す**（ここで詰まる問題を海上で発見するのが最悪パターン）
3. スマホ用防水袋（ジップロックで可）を艇数ぶん用意

**練習当日（各艇のスキッパー or 乗せる係）** — やることは2つだけ:
- **出艇前（岸で）**: アプリを開き「記録開始」を押す → 画面ロック → 防水袋 → 艇内の定位置（バウバッグ等）へ。**低電力モードはOFF**（バックグラウンド記録が止まる端末があるため）
- **着艇後（岸で）**: 記録停止 → 「GPXで書き出し」→ マネ艇担当のLINEに送る

**マネ艇担当（着艇後5分）**: 集まったGPXをファイル名「日付_セール番号.gpx」に直して部のGoogleDriveフォルダへ。帰着→共有完了までの所要時間をメモ（計測対象）。原本GPXは消さない（**主役がE2に決まった場合、このGPXがそのままsailvlog MVPのシードデータになる**）

### 2-3. 反省会の実施手順（既製ツール: 第一候補 raceQs / フォールバック TackTracker）

**第一候補: [raceQs](https://raceqs.com/)** — 無料・GPXアップロード可・艦隊再生あり。既知の制約2つ:
- **1アカウント1日1トラックの設計**のため、複数艇の同時再生は**艇ごとにアカウントを分けて各自のGPXをアップロード**する（[公式フォーラム](https://raceqs.com/forum/topic/creating-a-race-from-multiple-gpx-files/)）。同時刻・同海域のトラックは艦隊リプレイとして重なる
- GPXアップロードの**動作不安定報告**が公式フォーラムにある（[GPX file uploads](https://raceqs.com/forum/topic/gpx-file-uploads/)）。無料である点を買って第一候補に置くが、盲信しない

**フォールバック: [TackTracker](https://tacktracker.com/web/solution)** — GPX等のインポートと複数艇リプレイに対応（[PC Player解説](https://tacktracker.com/pcguide/importexport/)）。ただし**クラウドでの視聴は無料だが、Race Libraryへのトラックアップロードにはライセンス（Track Loader等）が必要**。PC版でのローカル再生が無料範囲で足りるかは**Day 0リハで要確認**（足りなければ検証2週間だけの最小ライセンス費用を部予算と相談 — その場合「0円検証」の看板は下ろすことを明記する）

**決着ルール: Day 0の陸上リハで実GPXを両方に通し、「複数艇が同一画面で再生できた方」を採用。** 両方動いたらraceQs（無料が確実）。両方動かなかったら[gpx.studio](https://gpx.studio/)等の汎用GPXビューアで航跡の重ね表示だけ行い、「時刻同期再生は既製ツールでは満たせない」という記録を残す（これ自体がsailvlogを作る根拠データになる）。

**反省会の進め方**:
1. 【事前・オーナー30分】各艇の記録者に当日GPXを採用ツールへアップロードしてもらう（Day 0リハでこの動線も1回通す）
2. 【反省会・最初の15分だけ】プロジェクタかPCでリプレイを再生。**進行台本**: ①スタート前後を再生「位置とタイミング、狙い通り?」 ②1上レグで一時停止しながら「このタック、なぜここで返した?」を各ペアに1回ずつ聞く ③記録係（マネ可）が出た発言を箇条書きでメモ（このメモがE2計測の原資料）
3. 残りの反省会は普段通り。**リプレイは15分で切る**（長引くと「リプレイのおかげか、時間を増やしたおかげか」が分離できない）

### 2-4. E2計測表

| 指標 | 数え方 | 結果 | PASS基準 |
|---|---|---|---|
| 収録成功率 | 成功トラック数 ÷ 試行数（例: 2練習×3艇=6試行）。**失敗理由も分類して記録**: 録り忘れ / 電池 / 防水 / 操作ミス / アプリ不具合 | /　 | **2/3以上**、かつ練習2回とも最低2艇ぶん揃う |
| GPS精度の主観評価 | 反省会後、参加者に挙手で確認「タックの位置と順番、議論に使えるレベルだった?（航跡がジグザグに暴れていないか）」5段階・2名以上に聞く | | **中央値3以上**。「艇の位置関係が逆に見えた」等の致命例が出たら理由を記録 |
| 反省会での発言変化 | リプレイあり回の「具体的な位置・時刻を指した発言」数 vs なし回（§3の週1反省会を対照群にする。記録係のメモで数える）。**「リプレイを見て初めて出た論点」の数も併記** | あり:　 なし:　 新規論点:　 | **あり回 > なし回**（厳密な統計は求めない。体感差＋メモの差で判定。新規論点は参考値） |
| アップロード所要時間 | 帰着→共有フォルダ格納完了まで（マネ艇担当のメモ） | | （参考値。長いほど本番の収録ハンドブック設計で吸収すべき負荷） |
| 運用負荷の主観 | マネ艇担当に聞く「毎練習これを続けられる?」 | | 「続けられる」（ここがNoなら成功率が高くてもE2は脆い） |

**E2判定 = 収録成功率・GPS精度・発言変化の3つすべて満たせばPASS。** 運用負荷Noの場合はPASSでも備考に赤字で残す（MVPの収録ハンドブック設計に直結）。

### 同時にやる小タスク（検証と独立・低コスト）

- **TracTrac KML有効イベント探索は追加調査済み（2026-07-24・打ち切り可）**: KML出力は主催者がイベント単位で有効化する仕組みで主に[Njord連携用](https://www.sailnjord.com/data-sources/tractrac/)。[ILCA UK等のイベント](https://tractrac.com/event-page/event_20251009_ILCAUKNati/3373)でリプレイ閲覧は恒久公開されているが、**第三者が自由にKMLダウンロードできる470/ILCAイベントは未発見**。現実的な入手経路は「主催者への直接依頼」のみ。→ **シード教材は自部収録データを主とする（PRD §7第3リスクの通りMVP成立に影響なし）。これ以上の探索時間は使わない**
- **案Fヒアリング（オーナー→部員へ、5分）**: 「上手い人のタック動画、今どこで見てる? 部のInstagram/LINEで足りてる? 誰が撮る?」— Fの既存代替の強さ（PRD §4）を一次情報で確認し、結果を§5に1行メモ

## 4. 判定マトリクス（PRD §4・GATES ①と整合）

| A | E2 | 判定 | 次アクション |
|---|---|---|---|
| PASS | PASS | **E2主役 + Phase 2でA接続**（PRD推奨どおり） | architectへ。PRD §5のMVPスコープで着手。収録GPXをシードデータに |
| FAIL | PASS | **E2主役**。A接続は保留 | architectへ。Aは「カードが書かれなかった理由」（空欄率・ヒアリング）を分析し、Phase 2で項目再設計してから再検証 |
| PASS | FAIL | **A主役**（GATES ①の取り決めどおり） | PRD rev.1のAスコープを§5に差し替え→architectへ。E2のFAIL理由が「精度」なら安価GPSロガー購入（部予算・PRD §7第2リスク）を見積ってPhase 2候補に残す。「収録が続かない」ならE2は棚上げ |
| FAIL | FAIL | **PRDへ差し戻し**（両FAILは「データ供給が続かない」という最大リスク仮説の的中） | 主役6案の前提=「部がデータを供給する」自体を疑う。B(TrimLab単独)やNO-GOを含めて再判断。**ここでGO延命のために基準を緩めない** |

**境界例の扱い**: 数値が基準の±1割に収まる「惜しいFAIL」は、1週延長して再計測してよい（1回だけ）。基準そのものの事後変更は禁止。

### product-leadからの自己反論（説得耐性）

この検証設計の弱点を先に言っておく: **n=1部・2週間・対照1回では統計的な有意差は出ない。** ここで測れるのは「供給が物理的に成立するか」と「現場の体感差」まで。E2の発言変化がPASSでも「新しい道具への物珍しさ」の可能性は排除できない（PRD §6のPhase 1・8週計測がその再検証にあたる）。それでも実装前のこの2週間には価値がある — 両FAILなら**数百時間の実装を0円で回避できた**ことになるからだ。
