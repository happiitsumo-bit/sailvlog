## 1. 目的 — なぜこの機能を作るか

セーリングにおける「セールトリム（帆の調整）」は、**最も抽象的で言語化が難しい技術領域** です。

- 風が見えない
- 帆の上で起きている気流の剥離・揚力発生が見えない
- 「もう少しシートを引いて」が、どの程度の角度変化なのか、初心者には分からない
- 中級者になっても「なぜ強風時にトラベラーを落とすのか」を**理論で説明できる人は少ない**

sailvlog の `Learn` セクションは現状、コース構成（Beginner / Intermediate / Advanced）の入口はあるものの、**「動く図解」がない教科書状態** です。本機能 TrimLab は、

1. 物理理論に基づいた**揚力・抗力ベクトル**をリアルタイム表示
2. シート角度・風速・風向の操作に即応する**動く図解**
3. 失速・揚抗比という**中級者向けの定量的指標**

を提供することで、Learn コンテンツの**学習効果を質的に引き上げる** ことを目的とします。

### 関連する既存実装

- `/learn` のコース一覧ページ — 本シミュレータの "玄関口" になる
- `lib/mock-references.ts` のリファレンス記事 — 失速・揚抗比などの解説本文へのリンクで往復導線を作る

### 3.2 真上視（メイン Canvas）

- **ボート:** 中央に細長い楕円。船首は画面上方。
- **セール:** ボートの上に短い直線。シート角度に応じて開閉。
- **風向矢印:** 画面の隅から真風（True Wind）の方向を示す太い矢印（`var(--fg-mute)`）。
- **見かけの風 (Apparent Wind):** ボート速度ベクトルと合成した見かけの風を別色で表示（`var(--dijon)`）。Phase 1では「真風＝見かけの風」と簡略化することも可。
- **揚力ベクトル L:** 帆面に垂直な方向、`var(--sage)`
- **抗力ベクトル D:** 見かけの風に平行な方向、`var(--fg-dim)`
- **推進力 Fx (Drive Force):** ボート船首方向の合力成分、`var(--terra)` 太矢印
- **ヒール力 Fy (Heeling Force):** ボート横方向の合力成分、`var(--dijon)` 太矢印

各ベクトルの長さは、現在のパラメータでの大きさ（N または相対値）に比例。

### 3.3 後方視（サブ Canvas、小さく並列）

- 画面の右側に幅 30〜35% で配置
- **見るもの:** マスト断面とセール断面、ヒール角
- Phase 1 では「ヒール力 Fy → ヒール角 θ ≈ atan(Fy / 復元力)」の単純モデルで傾きを表現
- **意図:** Step 3 で Three.js でツイスト表現に発展させる伏線。今は「同じ現象を別視点で見る」体験を成立させる

## 4. 物理モデル — 中級向けに失速・揚抗比まで表現

### 4.1 基本式

帆に作用する力は流体力学の標準形：

```
L = 0.5 × ρ × V² × S × Cl(α)
D = 0.5 × ρ × V² × S × Cd(α)
```

- ρ = 空気密度（1.225 kg/m³ 固定）
- V = 見かけの風速 [m/s]
- S = 帆面積（10 m² 固定、相対比較のため）
- Cl(α) = 揚力係数（迎角 α の関数）
- Cd(α) = 抗力係数（迎角 α の関数）

### 4.2 迎角 α の定義

- 真風向 θ_tw、ボート進行方向は y軸（θ = 0）
- 見かけの風 = 真風 − ボート速度ベクトル（Phase 1 はボート速度を仮定 or 0）
- 帆の向き = シート角度 θ_sheet（ボート船首基準）
- 迎角 α = 見かけの風と帆面の角度

```
α = (見かけの風の方向) − (帆面の方向)
```

### 4.3 Cl(α) / Cd(α) — 失速を含む近似曲線

教科書的な薄翼モデルでは Cl = 2π × sin(α) ですが、本シミュレータでは**失速を含む現実的な近似** を使います：

```typescript
// 失速角 αs（典型値：15°）を境に、Cl が一気に落ちる
function Cl(alpha: number): number {
  const alphaStall = 15 * Math.PI / 180;  // 失速迎角
  if (alpha < 0) return 0;                 // 逆風はラフィング
  if (alpha < alphaStall) {
    // 線形領域：Cl = 2π × sin(α) を簡略化
    return 2 * Math.PI * Math.sin(alpha);
  }
  // 失速後：迎角が大きくなるにつれて Cl が下降
  const overshoot = alpha - alphaStall;
  const decay = Math.exp(-overshoot * 3);
  return 2 * Math.PI * Math.sin(alphaStall) * decay * 0.7;
}

function Cd(alpha: number): number {
  const Cd0 = 0.05;  // 形状抗力
  // 誘導抗力（揚力に比例して増える）
  return Cd0 + 0.1 * Cl(alpha) ** 2 / Math.PI;
}
```

これにより：

- **迎角 0〜15°:** Cl が上昇、揚力増加（理想的トリム）
- **迎角 15° 付近:** 揚抗比のピーク
- **迎角 15° 以上:** 失速、Cl 急落、抗力増加（オーバートリム）

### 4.4 推進力 / ヒール力への分解

帆面に作用する合力 F = (L⊥, D∥) を、**ボート進行方向（x軸）とそれに垂直な方向（y軸）に分解**：

```
Fx (推進力) = L × sin(δ) − D × cos(δ)
Fy (ヒール力) = L × cos(δ) + D × sin(δ)
```

ここで δ は「真風と帆の合力ベクトルとボート進行方向のなす角」。詳細は実装で。

### 4.5 状態判定

```typescript
type SailState = "luffing" | "good" | "near-stall" | "stalled";

function classifyTrim(alpha: number): SailState {
  const a = alpha * 180 / Math.PI;
  if (a < 3)  return "luffing";       // 風上振れ
  if (a < 12) return "good";          // 良トリム
  if (a < 15) return "near-stall";    // 失速直前
  return "stalled";                    // 失速
}
```

### 4.6 これは「中級者向け」のラインなのか？

YES。教育用簡易モデル（線形 Cl のみ）では失速・揚抗比の概念が出てこないため、**「なぜ強風時にシートを少し緩めるのか」「なぜ無風時はシートを引きすぎてはいけないのか」** といった**現場で実際に出る疑問** に答えられません。

本モデルは流体力学の本格モデル（CFD）ではなく、教科書レベルの「失速含み近似」ですが、**初心者→中級者への橋渡し** として必要十分です。

## 7. 新しく登場する概念・技術

### 7.1 HTML5 Canvas API

**何か:** ピクセル単位の2D描画ができるブラウザ標準API。SVGと違って「ベクター要素」ではなく「絵を塗りに行く」スタイル。アニメーション・大量の図形描画で軽い。

**今回の使い方:**

```tsx
const canvasRef = useRef<HTMLCanvasElement>(null);

useEffect(() => {
  const canvas = canvasRef.current;
  if (!canvas) return;
  const ctx = canvas.getContext("2d");
  if (!ctx) return;

  // クリア
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // ボート描画
  ctx.beginPath();
  ctx.ellipse(cx, cy, 20, 60, 0, 0, Math.PI * 2);
  ctx.strokeStyle = "var(--fg)";  // ← これは効かない（後述）
  ctx.stroke();
}, [sheetAngle, windSpeed, windDir]);
```

**注意:** Canvas の `strokeStyle` は CSS変数を直接受け取れません。`getComputedStyle(document.documentElement).getPropertyValue("--terra")` で取得してから渡す必要があります。これは TrimSimulator 内に `getToken()` ヘルパーを置いて対応します。

**応用例:**
- グラフ・チャート描画（Chart.js も内部は Canvas）
- ゲーム（ブロック崩し、シューティング）
- 画像処理（フィルタ、リサイズ）
- 手書き署名・お絵かきツール

### 7.2 requestAnimationFrame（rAF）

**何か:** ブラウザの描画サイクル（通常60fps）に同期して、指定した関数を呼び出すAPI。`setInterval` より滑らかで、タブが非アクティブのときは自動的に止まる省エネ仕様。

**今回の使い方（Phase 1 では使わないが将来の拡張で）:**

スライダー操作だけなら state 変更で再レンダリングすれば十分なので、rAF は使いません。ただし将来「風が時間とともに揺らぐ」「波の影響でセールがフラッタする」演出を入れるなら rAF が必要になります。

```tsx
useEffect(() => {
  let frame: number;
  const tick = () => {
    setT((prev) => prev + 0.016);  // 約16msごとに t を進める
    frame = requestAnimationFrame(tick);
  };
  frame = requestAnimationFrame(tick);
  return () => cancelAnimationFrame(frame);
}, []);
```

**応用例:**
- スクロール連動アニメーション
- パーティクル演出
- リアルタイム可視化（株価チャート、センサー値）

### 7.3 純粋関数としての物理モデル

**何か:** 「同じ入力なら必ず同じ出力を返し、副作用がない」関数の作り方。`lib/sail-physics.ts` を React と切り離して書くことで、

- ユニットテストが書きやすい
- 別UIに移植しやすい（例: Storybook、別ページでの再利用）
- 物理モデルの差し替えが容易

**応用例:** ビジネスロジック・状態遷移・ゲームのスコア計算など、「データの変換」はすべて純粋関数で書くべき。React コンポーネントから関数を引き剥がす習慣がついてくると、コードベース全体が一段スッキリします。

### 7.4 揚力（Lift）/ 抗力（Drag）/ 揚抗比（L/D ratio）

**何か:** 流体力学の3つの基本概念。航空機の翼設計、自動車の空力、ヨットの帆、すべて共通の枠組み。

- **揚力 L:** 流れに**垂直**な方向に発生する力
- **抗力 D:** 流れに**平行**で**逆向き**の力（抵抗）
- **揚抗比 L/D:** 効率指標。「同じ揚力を出すのに、抗力がどれだけ少なくて済むか」

セーリングでは、揚力が「推進力＋ヒール力」に分解されます。揚抗比が高ければ「無駄な抵抗が少なく、しっかり前に進む」状態です。

## 10. 確認したいこと

1. **物理単位の表示** — 揚力・抗力を「N（ニュートン）」で出すか、「相対値（0〜100の正規化）」にするか？  N は現場感がない一方、相対値は教育的だが「実際の数値」感が弱い。**推奨:** 相対値（0〜100）で表示し、ホバー時に N 換算を出す
2. **真風 vs 見かけの風** — Phase 1 ではボート速度を 0 として「真風＝見かけの風」と簡略化してよいか？（中級者には少し物足りないが、見かけの風を導入すると初心者には難しすぎる）
3. **失速時の演出** — 失速状態のときに帆を「フラッタリング」風にチラつかせる表現を入れるか？（rAF が必要になるが、教育効果は高い）

承認後、段階1から実装に着手します。
