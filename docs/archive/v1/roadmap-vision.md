# sailvlog ロードマップ＆ビジョン
## 〜ヨット界の技術の断絶を解決する、知の継承プラットフォーム〜

**バージョン:** 1.0  
**作成日:** 2026-05-20

---

## 1. プロジェクトの本質（Motto）

> **「ヨット競技の技術情報は、見つけにくいか、そもそも存在しない。」**
> この課題を、知の継承インフラを作ることで解決する。

sailvlogは「個人ブログの集合体」ではなく、**ヨット界の集合知が体系化される場所**を目指す。

---

## 2. コア原則（Core Principles）

| 原則 | 意味 | 具体的な反映 |
|------|------|------------|
| **Legacy（継承）** | 卒業・引退で消える「部の知識」を蓄積する | 大学・チームページ（Phase 3） |
| **Reference（参照）** | 「これは何？」に即答できる辞書を持つ | Wikiページ（Phase 2） |
| **Dialogue（対話）** | 暗黙知を質問と回答で言語化する | Q&A 強化（Phase 2） |

---

## 3. 機能の優先順位（忖度なし版）

### ✅ Phase 1: PC基盤の整備（実装済み）
- 3カラムAppShell
- Ctrl+Kコマンドパレット
- 既存のFeed・Article・Q&A・Learnを活用できる土台

### 🎯 Phase 2: 知の集積を加速する（最優先・次に着手）

| 機能 | 目的 | 重要度 |
|------|------|------|
| **Reference（艇種・用語辞典ページ）** | 「470とは何か」「クローズホールドとは何か」に答える定義集 | ★★★ |
| **Q&A 解決済み検索の強化** | 過去の質問を素早く再利用できる | ★★★ |
| **タグ・艇種での横断検索強化** | Ctrl+K と連動した「知識の発見性」向上 | ★★ |

### 🌱 Phase 3: コミュニティの土台（Geminiの提案を一部採用）

| 機能 | 目的 | 重要度 |
|------|------|------|
| **大学・チームページ** | 部単位での技術アーカイブと公式ページ | ★★★ |
| **限定公開設定** | 「秘伝のタレ」を部内だけに共有 | ★★★ |
| **OB/現役メンバー機能** | 卒業しても知識を残せる構造 | ★★ |

### 🌐 Phase 4以降: 信頼性とスケール（ユーザー数次第）

| 機能 | 条件 |
|------|------|
| 認証セーラー制度 | アクティブユーザー1000人以上 |
| スポンサー連携 | 月間PV 10万以上 |
| ギアDB | 別プロジェクトとして独立検討 |

### 🔬 Phase 5: TrimLab Full Controls（開発末期・低優先度）

> 企画書: `docs/trimlab-full-controls.md`

**前提:** TrimLab Phase 1（`TrimSimulator.tsx.bak`）の復元完了後に着手

| 機能 | 内容 | 実装難易度 |
|------|------|------|
| **バング** | twistRatio への直接マップ | 低 |
| **トラベラー** | 実効迎角への ±補正 | 低 |
| **カニンガム** | Cl ピーク角シフト（ドラフト前後移動） | 中 |
| **アウトホール** | draftDepth モデル | 中 |
| **ジブシート + ジブリーダー** | 独立した第2迎角＋高さ方向ツイスト分布 | 中〜高 |
| **バックステー** | mastBend 補助パラメータ | 低 |
| **スロット効果（ジブ+メイン干渉）** | 2帆 Cl 干渉モデル | 高 |
| **XFOIL API連携**（将来） | Python FastAPI + XFOIL で本格的な圧力分布 | 大 |

**目標:** 「シートを引く」ではなく「帆を作る」体験。日本語で公開されているセールトリムシミュレータとして唯一無二の存在を目指す。

## 4. 採用しない・後回しにする機能（理由付き）

| 機能 | 判断 | 理由 |
|------|------|------|
| 派手なFeed強化（SNS化） | ❌ | 知の蓄積に寄与しない。流れて消える情報を増やす意味はない |
| スポンサー機能（Phase 3で導入） | ❌ | ユーザー0の段階で広告UIを設計するのは本末転倒 |
| Gear Tech DB | ❌（別プロジェクト） | 構造化データと暗黙知は別ツールが扱うべき |
| 認証バッジを今すぐ | ❌ | 権威主義的なUIは新規ユーザーを萎縮させる |

---

## 5. 「あなたの信念」と「UI/UX」の整合性チェック

### ✅ 整合している部分
- Ctrl+Kコマンドパレット → 「探しにくい問題」への直接的な解
- Q&A機能 → 「対話で技術を言語化する」コア機能
- 艇種カラーシステム → ヨット競技の構造を反映したナビゲーション

### ⚠️ 整合性が弱い部分（今後改善）
- **Reference（用語・艇種定義）の不在** → Phase 2で最優先
- 記事カードのUIが「ブログ寄り」 → Phase 2で「ナレッジカード」への進化を検討
- Feedが目立ちすぎる → 知の集積を阻害するため、ホームでの優先度を下げる

---

## 7. 一言で言うと

> **sailvlogは「ヨット界のWikipedia + Stack Overflow」を目指す。**
> 大学ページもスポンサーも、その上に乗る付加価値であって、土台ではない。

土台 = **検索しやすい知識データベース**。  
これがブレなければ、UI/UXの判断軸は明確になる。
