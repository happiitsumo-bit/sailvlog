# sailvlog v2 — コンテンツモデル（L3：判断の型）

> **このドキュメントが扱う問い:**
> セーリングは「その時々で最適解が違う」（波高・風速・風の振れ・セッティングの組み合わせで答えが変わる）。
> 固定の答えを載せると嘘になる。では sailvlog は、何を・どう載せるのか？
>
> **結論: 個別の答え（L2）ではなく、「なぜそうなるか」の因果モデル（L3）を載せる。**
> タクミが「今日の海」に自分で当てはめて判断できるようにする。

**作成日:** 2026-06-09
**前提:** [[00-persona]]（タクミ／速くなりたい）, [[01-prfaq]]（リリースの定義）

---

## 1. なぜ L3（因果モデル）なのか

### 答えの3レベル

| レベル | 形 | 例 | 評価 |
|--------|-----|-----|------|
| L1 | 固定の答え | 「バングを引くと速い」 | ❌ 条件無視で嘘になる |
| L2 | 条件付きの答え | 「微風×波あり なら緩める」 | △ 組み合わせが爆発・網羅不能 |
| **L3** | **判断の型（因果モデル）** | 「バングは"ツイスト量"を決める／ツイストは"風の上下ムラ"に合わせる」 | ✅ **採用** |

### L3が解決すること
- **「その時々で違う」問題**を、答えの暗記ではなく**原理の理解**で乗り越える。
- タクミは「今日は強風で海面が荒れている → 上の風を逃がしたい → ツイスト増やす → バング緩める」と**自分で導ける**。
- **項目数が爆発しない**。原理は1つ書けば、無数の条件に応用が効く → **運営一人でもシードを書き切れる**（コールドスタート回避と直結）。

## 2. L3コンテンツの構造（テンプレート）

各「トリム項目」は、以下の固定構造で書く。**これがコンテンツの型＝サービスの心臓部**。

```
# 【項目名】 例: バング（ボームバング）

## ① 何を操作するのか（物理）
このコントロールが帆の何を変えるのか、一文で。
例: バングはブームを下に引き、メインセール上部の「ツイスト（ねじれ）」を減らす。

## ② なぜ速さに繋がるのか（因果の鎖）
操作 → 帆の変化 → 力の変化 → 速さ、の因果を繋ぐ。
例: ツイストが減る → 上部の帆も風を受ける → 全体の推進力が増える。
    ただし強すぎると上部が失速し、ヒールとリーヘルムが増えて遅くなる。

## ③ 何に合わせて調整するのか（適合の軸）★最重要★
「正解」ではなく「合わせるべき変数」を示す。
例: ツイスト量は『風の上下のムラ』と『艇のオーバーパワー具合』に合わせる。
    - 風が上下で大きく違う（地上は弱いが上は強い）→ ツイスト多め＝バング緩め
    - オーバーパワー（風が強すぎて起こせない）→ 上を逃がす＝ツイスト多め＝バング緩め
    - パワー不足（微風で進まない）→ 全面で受ける＝ツイスト少なめ＝バング引く

## ④ 代表的な状況での目安（L2を例として最小限）
原理を裏付ける「例」として、2〜3ケースだけ。網羅はしない。
例: 微風・平水 → やや引く ／ 中風・適正 → 基準 ／ 強風・波あり → 緩める

## ⑤ よくある誤解・やりがちなミス
例: 「強風だからとにかく引く」は逆効果になりやすい（上が失速する）。

## 関連項目
[[カニンガム]]（ドラフト位置）, [[トラベラー]]（迎角）と組み合わせて効く。
```

### 設計上の肝
- **③「適合の軸」が主役**。ここが「その時々で違う」問題への直接の回答。
  「正解（緩める/引く）」を教えるのではなく「何を見て決めるか（風の上下ムラ）」を教える。
- **④は"例"として最小限**。L2を全部並べると爆発するので、原理を裏付ける数ケースに留める。

---

## 3. 「適合の軸」を支える共通言語（横串の概念）

個別項目がバラバラにならないよう、全項目が共通で参照する**少数の基礎変数**を先に定義する。
これがあると、タクミは「今日の海」をこの変数で読めるようになる。

| 共通変数 | 意味 | 各コントロールとの関係 |
|---------|------|---------------------|
| **パワー（過不足）** | 風に対して艇を起こせているか | 過剰→逃がす方向、不足→受ける方向 |
| **ツイスト** | 帆の上下のねじれ | バング・メインシート・リーチで操作 |
| **ドラフト位置** | 帆の最も膨らむ点の前後位置 | カニンガム・アウトホールで操作 |
| **迎角** | 帆が風に対して開く角度 | シート・トラベラー・リーダーで操作 |
| **海面状態** | 波の有無・大きさ | 加速の必要性 → パワー方針を左右 |

→ 各項目の③は、必ずこの共通変数のいずれかに紐づける。
   こうすると「バングもカニンガムも、結局パワーとツイストの話」と**体系**になる。
   （これがロードマップの "Reference（体系的な辞書)" の本来の姿）

## 4. このモデルが将来のTrimLab（シミュレータ）と繋がる理由

- L3は「操作 → 帆の変化 → 力 → 速さ」の**因果モデル**。
- TrimLab（物理シミュレータ）は、まさにこの因果を**動かして見せる**もの。
- つまり L3の辞書は、将来 TrimLab の「言葉による説明レイヤー」になる。
- **今は文章でL3を書く。将来それを可視化するのがTrimLab。** スコープは分けるが思想は地続き。

## 5. リリース時にこのモデルで埋める範囲（01-prfaqと整合）

- 470 or ILCA の**主要コントロール 10〜15項目**を、この②③④構造で書き切る。
- セクション3の**共通変数（5つ）**を先に定義しておく。
- 網羅（L2の全条件）はしない。**原理（L3）＋代表例（数ケース）**でリリース可。
