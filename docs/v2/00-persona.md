# sailvlog v2 — ターゲットペルソナと根源的欲望

> このドキュメントは「誰のために作るか」を**極限まで解像度を上げて**言語化したもの。
> 迷ったときは「この一人が喜ぶか？」だけを判断基準にする。「みんなのため」は禁句。

**作成日:** 2026-06-09
**位置づけ:** v2設計の最上流。01-prfaq / 02-design-principles はすべてこのペルソナから逆算される。

---

## 1. たった一人のペルソナ

### 名前（仮）：タクミ

> **具体度の注記:** タクミは「どこかの学生セーラー」ではない。**プロジェクトオーナーの大学のヨット部の後輩**。
> 顔が浮かぶ一人。コンテンツを書くとき「この後輩に刺さるか」が判断軸になる。

| 属性 | 設定 |
|------|------|
| 立場 | **同じ大学のヨット部の後輩**（1〜2年生・現役・レギュラー争い中） |
| 艇種 | 470 のクルー（もしくはスキッパー） |
| 競技歴 | 大学から始めて1年前後。基礎動作は身についたが、**「なぜ速いのか」の理屈がまだ曖昧** |
| 環境 | 平日は座学・筋トレ、週末に海で練習。**海にいる時間は週2回・限られている** |
| デバイス | スマホがメイン。練習後の電車・寝る前にベッドでスマホを触る |
| 情報源 | 先輩（オーナー含む）の口頭アドバイス、YouTube（英語が多くて辛い）、たまにヨット雑誌 |

### タクミの「いま」

- 先輩に「もっとセールを開けろ」と言われたが、**「なぜ・どれくらい・どういう状況で」が腹落ちしていない**。
- ネットで「470 セールトリム」と検索しても、**断片的なブログか、英語の動画**しか出てこない。
- 部の「秘伝のノウハウ」は4年生の頭の中にあり、**引退と同時に消える**。後輩の自分は毎年ゼロから探り直している感覚がある。

## 2. 根源的な欲望（表面ニーズの奥にあるもの）

### 表面的なニーズ
> 「セールトリムの調整方法を知りたい」「用語の意味を調べたい」

### その奥にある根源的欲望（★これが軸★）
> # 「速くなりたい。レースで勝ちたい。」

タクミが情報を探すのは、知識欲のためではない。**次のレースで前を走りたい**から。
「調整を知る」は手段にすぎず、ゴールは**「あの艇を抜く」瞬間の高揚感**にある。

### この欲望がサービス設計に与える決定的な影響

| もし欲望が… | サービスは…になる |
|------------|-----------------|
| 「置いていかれたくない（不安）」だったら | 網羅的な安心の辞書（あらゆる基礎用語を載せる） |
| **「速くなりたい（勝利欲）」← 採用** | **「速さに直結する実践知」を最優先する勝つための道場** |

→ 教科書的な定義（「クローズホールドとは風上に向かう帆走」）よりも、
**「微風の470で半艇身前に出るためのジブtrim」**のような、**勝負を分ける具体知**が主役になる。

## 3. 「使ったら成功」の定義

タクミがこうなったら、sailvlogは成功：

> **練習の帰りの電車で、その日コーチに言われた一言（例: 「もっとバング引け」）をsailvlogで調べ、
> 「なぜそれで速くなるのか」が30秒で腹落ちし、次の週末の練習で試して、実際に少し速くなる。**

このループが回れば勝ち。逆に言うと、これ以外の機能は今は要らない。

## 4. もう一人のペルソナ：「書く人（作者）」

読む人（タクミ）だけでは、サービスは続かない。いつか「書く人」が必要になる。
ただし v2 では **読む体験に集中**し、書く人の支援機能は次フェーズに回す。理由は下記。

### 作者ペルソナ（仮）：先輩・コーチ／競技経験者

| 属性 | 設定 |
|------|------|
| 立場 | 引退間近の4年生・OB・コーチなど、**経験知を持つ人** |
| 動機 | 「自分の試行錯誤を後輩に残したい」「部の知識を消したくない」 |
| 障壁 | **白紙に記事を書くのは面倒**。何をどう書けばいいか分からない |

### なぜ v2 では作者支援を後回しにできるのか（重要な論理）

- コンテンツの心臓部を **L3（因果モデル）** に決めた（→ [[02-content-model]]）。
- L3は「原理を1つ書けば無数の条件に応用が効く」ため、**項目数が爆発しない**。
- だから **運営（オーナー）一人でもシードを書き切れる量**に収まる。
- → 「大量の作者を急いで集める」必要がない。だから足場機能は今は不要。
- これは「コールドスタート問題」回避戦略（Stack Overflow / Reddit 初期と同じ）。

### 将来、作者を迎えるときの設計メモ（v2スコープ外・備忘）

作者の障壁「白紙が面倒」を下げるのは **運営が用意する「足場（スキャフォールド）」**：
- セールの**断面図テンプレート**（作者は数値・矢印を描き込むだけ）
- [[02-content-model]] の **②③④構造の穴埋めフォーム**（白紙でなく型を埋める）
- 風域別の入力枠

→ 運営は「コンテンツ全部」ではなく「**作者が書きやすくなる型・部品**」を用意する側に回る。
   これが読者と作者を繋ぐ橋。**ただし実装は読む体験が固まってから。**

## 5. 一言で

> **sailvlogは、現役学生セーラー「タクミ」が、練習帰りのスマホで“勝つための答え”に最短でたどり着く場所。**
