# sailvlog v2 — v1 実装棚卸し

> **目的:** v2 のリリースライン（[[01-prfaq]] PART3）に到達するために、現状の v1 実装のうち
> **「残す／保留／捨てる」** を一つずつ判定する。v2 3原則（[[03-design-principles]]）が判定軸。
>
> **判定軸（リマインド）:**
> 1. 速くなるのに直結するか？
> 2. 「判断の軸」を渡しているか？（L3か）
> 3. 読む密度を上げるのに、それを優先する理由があるか？

**作成日:** 2026-06-09
**前提:** [[00-persona]] / [[01-prfaq]] / [[02-content-model]] / [[03-design-principles]]

v2 の作業は「Reference + モバイル + コンテンツ」だけに集中する。

## 1. 領域別の評価

### 1-1. Reference（辞典）🟢 **残す（要 v2 改修）**

**現状:**
- `frontend/src/app/reference/page.tsx`（一覧）/ `[slug]/page.tsx`（詳細）
- `frontend/src/lib/mock-references.ts` に 37エントリ（艇種・技術・ルール）
- 詳細ページは ①概要 → ②本文（Markdown） → ③関連リンク の素朴な3段構成

**v2基準での評価:**
- ✅ **位置づけはサービスの心臓**（[[01-prfaq]] と完全一致）
- ❌ **コンテンツは L1〜L2 止まり**：「ダウンホール = 引くとパワー減」のような定義レベル
- ❌ **③適合の軸（風の上下ムラ / パワー過不足 / 海面状態）が項目に存在しない**
- ❌ **詳細ページの構造が L3 テンプレート（①〜⑤）に対応していない**
- ❌ **「艇種」「ルール」がスコープに混ざっている**：v2 はトリム実践知に集中
- ✅ **URL構造（`/reference/[slug]`）はそのまま使える**

**やること:**
1. 詳細ページを **L3 テンプレート構造**に作り変える（①物理 / ②因果 / ③適合の軸 / ④例 / ⑤誤解）
2. データ型 `ReferenceEntry` に L3 フィールドを追加（後方互換のため `body` も残す）
3. 既存の艇種・ルール項目は「カテゴリ:辞典補助」として残し、トリム項目とは別表示
4. 「共通変数（5つ）」の独立ページを `/reference/glossary` などに設ける

### 1-2. モバイル最適化 🟢 **残す（要 強化）**

**現状:**
- `globals.css` でレスポンシブは一定考慮されているが、PC 3カラム前提の名残あり
- コミット `3003928` で「モバイルでも見やすいように」UI改修済み

**v2基準:**
- ✅ タクミの主デバイス。**ここを死守するのがリリース基準**
- ⚠️ Reference 詳細を **「スマホで30秒で読める」** か未検証

**やること:**
- L3 詳細ページ実装時に **モバイル ファースト** で組む（PCはセカンダリ）
- フォントサイズ・行間・タップ領域を、片手でスクロールしながら読める設計に

### 1-3. Articles（記事投稿・一覧）🟡 **保留（凍結）**

**現状:**
- `articles/`、`articles/[slug]/`、`articles/new/`、`tag/[slug]/`、`boat/[slug]/`
- バックエンド: `routes/articles.ts`、`routes/tags.ts`、`routes/comments.ts`
- Markdown投稿・タグ・艇種カテゴリ・コメント・いいね・ブックマーク

**v2基準での評価:**
- ❌ 投稿機能は **v2 スコープ外**（[[01-prfaq]] Q3）：シードは運営が書き切る
- ⚠️ 既存記事を「読む」用途は L3 に集約されるので Articles ページに依存しない

**判定:** **凍結**（コードはそのまま残す。新規開発・改修はしない）

### 1-4. Questions / Q&A 🟡 **保留（凍結）**

**現状:**
- `questions/`、`questions/[id]/`、`questions/new/`

**v2基準:**

**判定:** **凍結**

### 1-12. テーマ刷新（claude-paper / editorial redesign）🟢 **残す**

**現状:**

**v2基準:**

- ⚠️ ただし「装飾の自己満足」になっていないか要点検（原則1違反）

**判定:** **残す**。L3 ページを組むときに、このタイポグラフィを軸にする

## 2. 「捨てる」と「凍結」の使い分け

| 状態 | 意味 | 運用 |
|------|------|------|
| 🔴 **削除** | コードベースから消す | **今は一つもなし**。戻す可能性を残す |
| 🟡 **凍結** | コードは残すが触らない・リンクから外す | 上記の保留領域すべて |
| 🟢 **残す** | 積極的に v2 に組み込む・改修する | Reference / モバイル / テーマ |

**凍結の運用:**
- ナビゲーション（Navbar / Footer / Ctrl+K）から、凍結領域へのリンクは **段階的に削除可能**
- ただし「リンクを消す」のは Reference の L3 化が形になってから（足元を崩さない）

## 3. 次にやるべきこと（このドキュメントから直接導かれる優先順位）

### 最優先（リリースに直結）

1. **Reference 詳細ページを L3 テンプレート構造に作り直す**
   - 型定義 `ReferenceEntry` に L3 フィールドを追加
   - 詳細ページの JSX を ①〜⑤ セクションに作り直す
   - モバイルファーストで再設計

2. **「共通変数（5つ）」の解説ページを作る**
   - パワー / ツイスト / ドラフト位置 / 迎角 / 海面状態
   - 各 L3 項目の③が参照する横串の言語

3. **シードコンテンツを書く（運営=オーナーが）**
   - 470 or ILCA の主要トリム用語 10〜15項目
   - まず 1項目（例: バング）を書き切って型を検証する

### やらないこと（明示的に）

- Articles / Questions / Learn / Sailors / Teams への改修
- 認証系の追加機能（パスワード再設定の完成を急がない）
- PC 3カラムや Ctrl+K の機能追加
- TrimLab / 物理シミュレータ着手
